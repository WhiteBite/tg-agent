# ui_assets/ — фронтенд рабочего пространства

Рабочее пространство — это `ui.html` плюс статические ассеты здесь. Фреймворка
нет: ванильный JS, общие CSS-классы и рендереры. Точка входа — `workspace.js`,
экраны лежат в отдельных файлах (`workspace_entities.js`, `workspace_downloads.js`,
…), стили — в `workspace.css`, шрифт Inter — локально в `fonts/`.

## Что где

| Файл | Роль |
|---|---|
| `workspace.js` | оболочка: навигация, общие примитивы, `W.*`-хелперы |
| `workspace_*.js` | экраны (сущности, проекты, переписка, анализ, каталог, загрузки, движок, ссылки, настройки, глобальный поиск) |
| `workspace.css` | токены и классы-примитивы |
| `fonts/InterVariable.woff2` | локальный шрифт (внешних CDN/шрифтов нет) |

## Контракт дизайна

Источник истины по палитре, типографике, сетке и состояниям — `DESIGN.md`.
Ключевое, что легко нарушить:

- два акцента (Electric Iris и Ember Pulse), третьего не вводить;
- pill-first геометрия контролов, радиусы `--r1/--r2/--r3`;
- тёмная тема по умолчанию, светлая и системная — в настройках;
- без внешних скриптов/CDN/шрифтов/картинок — данные остаются локально;
- брейкпоинты 900px (меню) и 600px (стек), тач-цели от 44px, контраст ≥ 4.5:1.

## Проводка нового экрана

Ассет сам по себе не появится, его надо четыре раза подключить. Точки:

1. создать `ui_assets/workspace_<name>.js`;
2. добавить имя в whitelist `ui.py` (множество `allowed` в обработчике `/assets/`);
3. подключить `<script>` в `ui.html`;
4. добавить серверные маршруты в `workspace_api.py` / `workspace_views.py`.

Проверяется скиллом `add-workspace-screen` и `tests_workspace_api.py`.
