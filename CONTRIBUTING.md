# Contributing — tg-agent

Спасибо, что помогаешь улучшать проект. Этот файл — для людей; машинно-ориентированная
точка входа для агентов — `AGENTS.md` рядом.

## Требования

- Python 3.12 (в CI — `ubuntu-latest` + `setup-python` 3.12).
- Зависимости: `requirements.txt` (`telethon`, `mcp`, `cryptg`, `qrcode`, `Pillow`).

## Установка

```bash
python -m venv ~/.venvs/tg-agent
~/.venvs/tg-agent/bin/pip install -r requirements.txt
```

Аккаунт Telegram для разработки не нужен: весь офлайн-гейт идёт без сети и кредов.
Для ручной проверки живого поведения скопируй `.env.example` в `.env` (файл в
`.gitignore`) и заполни.

## Тесты

```bash
python test_offline.py
```

`test_offline.py` — собственный раннер (не pytest). Сто тридцать пять проверок
из основного файла плюс пятнадцать сабсьютов (`tests_db_core.py`, …), которые
запускаются подпроцессами. Он герметичен: `TG_ENV_FILE=""` отключает чтение
пользовательского `.env`, а `server.py` и `ui.py` поднимаются как настоящие
процессы (MCP stdio и HTTP). Зелёный прогон — условие коммита.

Что делать при изменениях:

- новое поведение — новый `check(cond, label, extra)` в подходящем `tests_*.py`,
  а не молчаливая правка существующей проверки;
- новый MCP-инструмент или гейт — обнови счётчики инструментов в `test_offline.py`
  и в `tests_manage.py` / `tests_downloads.py` / `tests_announce.py`;
- новый сабсьют — добавь его запуск в `test_offline.py` и в раздел «Проверено»
  в `README.md`.

## Стиль кода

- `ruff` — конфигурация в `ruff.toml`, CI гоняет `ruff check .`.
- Соблюдай существующий стиль: `from __future__ import annotations`,
  `X | None` вместо `Optional[X]`, сортировка импортов.

## Гейты безопасности

Любая возможность записи в Telegram или в индекс — за гейтом `TG_ALLOW_*` и
требует `confirm=True` на каждый вызов. Новый пишущий инструмент без гейта —
дефект безопасности, такой PR не принимается. Полная таблица — `docs/gates.md`.
Новый гейт добавляй сразу в таблицу и в счётчики тестов.

## Коммиты

Один коммит на задачу. Заголовок — тип-префикс и одна императивная строка
по-русски, до 100 символов; формат как в `git log`:

```
docs: счётчик офлайн-проверок 1355
mcp: tg_transcripts уважает STRICT_WATCH
workspace(ui): адаптив по брейкпоинтам
```

Тело — только если заголовок не объясняет WHY. Без атрибуции агента/модели и без
эмодзи. Ничего вне задачи не трогай и не откатывай чужие правки.

## Изменения и CHANGELOG

История ведётся в `CHANGELOG.md` по версиям (`0.1.0` → `0.18.0`). Значимую
пользовательскую фичу оформляй новой записью в разделе текущей версии: подзаголовок
и список изменений по файлам. Релиз и релиз-пост — скилл `release`.

## Что не коммитить

`.env`, `*.session*`, `*.sqlite*`, `*.jsonl`, `*.log`, `downloads/` — в
`.gitignore`. Сессия — это полный доступ к аккаунту.

## Куда что писать

- `README.md` — возможности и CLI.
- `DESIGN.md` — дизайн рабочего пространства.
- `docs/gates.md` — гейты и конфигурация.
- `AGENTS.md` и вложенные (`modules/`, `packs/`, `ui_assets/`) — инструкции для
  агентов и краткие карты подсистем.

Повторяемые процедуры (новый MCP-инструмент, пак, модуль, миграция, экран UI,
релиз) — скиллы в `.opencode/skills/`.
